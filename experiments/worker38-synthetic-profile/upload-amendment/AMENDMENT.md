# Worker38 prospective upload amendment

Status: metadata proposal only. The registered protocol and current implementation remain unchanged by this document. Both independent reviews and root adoption are required before implementing the composite or changing provider-wrapper validation. Tests and scientific execution remain unadmitted.

The registered sixty-second provider-upload phase needs to contain up to three official upload actions in the same forty-five-minute job. Three separate one-minute step timeouts renew the allowance; GitHub does not support fractional step timeout values. The pinned upload action has no aggregate deadline input. A second job introduces another scheduling/runner boundary, while direct invocation through runner cache internals is not a supported public action interface.

The proposed repair is one fixed local composite at .github/actions/worker38-upload/action.yml, invoked once with timeout-minutes:1. It contains only the already selected official upload-artifact action SHA ea165f8d65b6e75b540449e92b4886f43607fa02 and fixed ordinal paths. The production roster grows from sixteen to seventeen files. No custom HTTP client, new interpreter for science, arbitrary command/path/action option, new job, readiness allocation or additional measurement is introduced.

## Primary-source basis

GitHub documents a composite as a series of steps exposed as one job step: https://docs.github.com/en/actions/tutorials/create-actions/create-a-composite-action . Workflow timeout syntax requires a positive integer minute value: https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idstepstimeout-minutes . The pinned upload action's declared inputs and node20 runtime are available at https://github.com/actions/upload-artifact/blob/ea165f8d65b6e75b540449e92b4886f43607fa02/action.yml .

The accepted postmerge CI37250449266 log independently records runner version2.337.0. Exact tagged source confirms the mechanism: StepsRunner applies the caller step timeout; ExecutionContext.CreateEmbeddedChild passes GetRemainingTimeout() to each child context; child context installs that remaining timeout; CompositeActionHandler creates the nested steps through this path. References: https://github.com/actions/runner/blob/v2.337.0/src/Runner.Worker/StepsRunner.cs , https://github.com/actions/runner/blob/v2.337.0/src/Runner.Worker/ExecutionContext.cs , https://github.com/actions/runner/blob/v2.337.0/src/Runner.Worker/Handlers/CompositeActionHandler.cs . Raw files and hashes are preserved in primary-sources and AMENDMENT-CONTRACT.json. This is source confirmation of the reported version, not an independent binary measurement or a new runner probe.

The one-minute caller timeout covers composite preparation and its nested step sequence. Internal delays consume the same remaining interval; there is no second-job queue. Existing job and phase ceilings remain in force. Cancellation need not be instantaneous: an unknown, cancelled, failed or observed late upload cannot certify complete custody. The parent must check the actual composite interval/outcome and retain partial artifacts. No backend cancellation grace is represented as a renewed upload allowance.

## Three wrappers and the original compact manifest

The original compact transport manifest is generated after sealing/splitting the raw archive. It is outside that archive and binds archive bytes/hash, ordered parts and raw evidence inventory; it does not hash or include itself. To preserve it without a fourth provider upload, wrapper1 contains exactly part-001.bin and transport-manifest.json. Wrappers2/3, when required, contain exactly their respective part binaries. The first part remains at most30MiB, the separate manifest at most1MiB. Their sum is at most31MiB; actual downloaded ZIP must independently remain strictly below32MiB. This does not increase any original part, archive or raw-evidence payload cap, and the manifest bytes are never appended to the part stream.

Check exact member sets, safe regular names, duplicates, traversal, type, expanded size, CRC and full byte hashes before parsing the manifest as evidence. Bind its schema/order/hash/size/archive/inventory to all parts and reconstructed raw bytes. Canonical manifest upload/readback must equal the exact first-wrapper manifest bytes. Provider URLs or locally asserted hashes alone do not authenticate origin; parent connector evidence remains required. Missing/partial wrappers leave custody incomplete, with raw and confirmed artifacts preserved. No repackaging, replacement, retry or scientific continuation follows.

## Pre-transmission literal path and sealed ownership boundary

Pinned search.ts uses a glob matcher, follows symbolic links and permits implicit descendants. Therefore a canonical name can still select unintended bytes. The exact source is preserved at primary-sources/upload-artifact-ea165f8-search.ts and at https://github.com/actions/upload-artifact/blob/ea165f8d65b6e75b540449e92b4886f43607fa02/src/shared/search.ts .

Before science, require the canonical cache root and every later derived upload/plan pathname to use only ASCII letters, digits, dot, underscore, hyphen and slash. Require an absolute path, nonempty components, no dot/dot-dot component, no repeated or trailing slash and no alias. Reject every wildcard, bracket, brace, backslash, whitespace/control, tilde or other glob/control character. Do not escape a user-supplied pattern and assume equivalence. Only fixed part/manifest filenames and the validated decimal current run ID form suffixes.

During the original preservation interval, establish the no-follow component and payload proof before upload readiness. Validate the fixed private allocation/transport root, its custody ownership/permissions and each exact selected regular single-link file. Reject symlinks, redirects, special files, unexpected writers, incomplete process cleanup or uncertain observations. Retain original full hash/stat/size evidence, fsync all payload/plan bytes, and seal only these generated transport files/plan0400 and transport directory0500. Existing private ancestors remain unchanged; no system permissions or permanent access are modified.

The composite performs bounded builtin-only prechecks before each vendor action: exact literal derived paths, non-symlink components, expected directories and regular/readable/owned/read-only plan and selected files, strict fixed part count/names, and a <=4096-byte control read. It passes exact file paths, never a directory or wildcard. An invalid or unavailable source stops before the vendor invocation. It performs no new hash, copy, packaging, repair or permission reseal after the original preservation deadline.

This bounds the race under the existing trusted-runner custody model: one unique private namespace, confirmed completed writers, read-only payloads and no remaining authorized write path. It does not claim an atomic descriptor handoff to the vendor, nor immunity to an arbitrary malicious process with the same UID or root. If exclusive custody cannot be established, the attempt does not upload. A later observed change blocks remaining uploads and acceptance, but is not described as preventing an earlier transmission. Post-download ZIP/CRC/hash checks remain independently mandatory.
